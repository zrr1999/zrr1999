# Zendev Lab

Tools and experiments for building better software.

This organization collects repository-native workflow tools and local execution experiments. Each project owns a different problem. This page is a short map. Manuals and authoritative behavior stay with each project.

## Projects

| Project | What it owns | Start here |
| --- | --- | --- |
| [Zendev](https://github.com/zendev-lab/zendev) | Repository-native workflows: commit conventions, pull-request checks, proposals, and project evolution. | [Documentation](https://docs.zendev.zrr.dev/) |
| [Spark](https://github.com/zendev-lab/spark) | A local-first coding-agent runtime for durable sessions and supervised work. | [Documentation](https://docs.spark.zrr.dev/) |
| [Cue](https://github.com/zendev-lab/cue) | A durable local execution kernel. Clients submit a typed execution; the daemon owns process groups, output, and recovery. | [Repository](https://github.com/zendev-lab/cue) |

## Participate

Principles that apply across the organization are in [CONTRIBUTING.md](https://github.com/zendev-lab/.github/blob/main/CONTRIBUTING.md). A project with its own contributing guide uses that guide.

Questions about how to use a tool belong in that project's docs. Defects belong in that project's issues. Where to send each kind of request is in [SUPPORT.md](https://github.com/zendev-lab/.github/blob/main/SUPPORT.md). Problems with this page belong in [this repository](https://github.com/zendev-lab/.github/issues).
